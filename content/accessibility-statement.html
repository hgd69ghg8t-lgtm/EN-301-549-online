What this statement covers

This statement covers the accessibility of this website: the unofficial HTML edition of European Telecommunications Standards Institute (ETSI) EN 301 549. It does not cover the accessibility of any product or service being evaluated against the standard reproduced here.

Report an accessibility problem

Report an accessibility problem using the GitHub accessibility form. It asks for the page address, what happened, and what you were trying to do — everything else is optional.

Submitting a GitHub issue requires a free GitHub account. GitHub is not a dedicated public-sector accessibility contact channel, and this is currently the only way to report a problem with this website.

Accessibility target

We aim for this website to meet the Web Content Accessibility Guidelines (WCAG) 2.2 at Level AA.

The website has not been independently audited, so this is not a formal conformance claim.

Testing completed

Automated checks run whenever the website changes. They check common coding and accessibility problems, including colour contrast, heading structure and broken links. See Technical testing details below for exactly which tools and checks these are.

Automated checks can only catch a subset of accessibility problems. They cannot judge whether reading order makes sense to a real screen reader user, or whether keyboard interaction feels usable rather than merely operable.

Known issues

  • Manual screen-reader and keyboard-only testing has not yet been completed (see Testing still planned) — treat any specific assistive-technology compatibility as untested until this section says otherwise.
  • Some tables in the standard (particularly in Annex C and Annex ZA/ZB) are wide and need horizontal scrolling on narrow screens. These are marked as scrollable, focusable regions with an accessible label, but very complex tables can still be harder to follow with a screen reader than ordinary text.
  • This is a large, mostly text-based reference document. No attempt has been made to simplify the underlying legal or technical language of the standard itself — that would change the meaning of a normative document, and is out of scope for this website.

Testing still planned

A full manual evaluation, including real screen-reader and keyboard-only testing, has not yet been completed. The combinations below are the ones this project intends to test against — do not treat any of them as verified until they are recorded as tested in the manual testing log.

  • NVDA with Firefox or Chrome (Windows)
  • JAWS with Chrome or Edge (Windows)
  • VoiceOver with Safari (macOS)
  • VoiceOver (iOS)
  • TalkBack (Android)

Review history

No accessibility review has been completed yet. When one happens, it will be recorded here and in the manual testing log.

Technical testing details

The following automated checks run in continuous integration (CI) on every change to this website:

  • An automated accessibility scan (axe-core) against the WCAG 2.0 A/AA, 2.1 AA and 2.2 AA rule sets.
  • HTML validation, including invalid ARIA attribute usage.
  • Structural checks specific to this site: heading hierarchy, a single non-empty <h1> per page, no duplicate IDs, no malformed or unclosed tags.
  • Internal link and anchor-target checks (no broken same-site links, no dangling # fragments).
  • Colour-contrast ratios of the site's own design tokens (the colours defined in docs/assets/css/style.css).

What still needs a person, not a tool:

  • Whether the reading and focus order actually make sense.
  • Whether heading and link wording is genuinely descriptive out of context.
  • Real screen-reader and keyboard-only walkthroughs.
  • Cognitive load, plain-language clarity and overall usability.
  • Behaviour under browser zoom, reflow, forced-colours mode and reduced motion in real assistive-technology combinations.
